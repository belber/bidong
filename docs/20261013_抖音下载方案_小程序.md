# 抖音视频下载 —— 落地方案（给小程序后端）

> ⚠️ **2026-10-14 更正**：本文 §4.3 与 §12 第 8、9 条「必须带 iPhone/Android UA + `Referer: https://www.douyin.com/`，否则 403」
> 经复测**不成立**。实测 `v11-weba.douyinvod.com` 上的视频直链，不带 UA、不带 Referer、带微信 Referer 等 5 种组合全部返回 `206`；
> 图片 CDN（`douyinpic.com`）同样不校验。因此**不需要服务端中转**，直链可直接交给客户端，兜底弹窗沿用 B站 现有写法。
> 以 `docs/spec.md` §13 为准。

> 适用对象：现有「B站链接解析下载」小程序，新增抖音视频下载能力。
> 文档中所有 ✅/❌ 结论均为 **2026-10-13 实测**（测试出口：香港家宽住宅 IP，使用一个已登录的抖音账号 cookie；该 cookie 的 `sid_guard` 显示有效期至 2026-11-14，即 60 天）。
> 未实测的部分已明确标注为「常规做法 / 待验证」，不要当成已验证结论。

---

## 0. 结论先行（TL;DR）

1. **抖音没有一个「完全不需要账号」的稳定点播接口。** 网页接口有签名墙（a_bogus/x-bogus），移动端接口有登录墙（实测：只给设备级 cookie 一律返回 `HTTP 200 + 空 body`，必须先有 `sessionid` 系会话）。所以「永远不用 cookie」这件事做不到，**能做到的是「不用用户每周手动给你 cookie」**。
2. **推荐路线：一个专用抖音账号 + 服务端自持会话（自动保温/自动续期）**。会话寿命实测 **60 天**（`sid_guard=...|5184000|`），且活跃会自动续期；配健康检查 + 掉线告警，就能做到「上线一次、长期不用人管」。
3. **两类接口分工**（实测都通）：
   - **视频本体/音频/封面/作者/统计** → 移动端 `aweme.snssdk.com/aweme/v1/aweme/detail/`，**不需要签名，只需要登录态 cookie**，返回无水印直链（实测下载 4.6 MB MP4）。
   - **评论列表** → 网页端 `aweme/v1/web/comment/list/` + 自算 `a_bogus` + 登录 cookie，实测拿到 18 条（共 1997 条）。
   - 网页端 `aweme/v1/web/aweme/detail/`（带自算 a_bogus）实测 **403**，别在这条路上耗时间。
4. **图文（note）是独立难题**：移动端接口对图文一律回 `filter_reason: "images_base"`（拿不到图片），要单独走第三方/自建解析服务或真浏览器。
5. **弹幕：抖音点播视频没有弹幕**（只有直播有）。小程序里别做「抖音弹幕」按钮，可考虑用「评论」代替。
6. **出口 IP 很关键**：住宅/家宽 IP 明显更宽松（本机是香港家宽，实测移动接口 + 评论接口都通），**腾讯云机房 IP 未测**，务必先做第 12 节的探活，再决定是否挂家宽代理。

## 2. 抖音风控的三道门

要让抖音把视频数据给你，必须同时满足三个条件，缺一不可：

| 门 | 是什么 | 谁提供 |
|---|---|---|
| **签名** | `a_bogus` / `x-bogus` / `msToken`（网页接口用） | 自己算（开源实现）或让真浏览器页面帮你发请求 |
| **身份** | 登录态 `sessionid` 系（网页/移动接口都认） | 一个抖音账号；设备级 cookie **不够**（实测 #9） |
| **出口 IP** | Argus 按 IP 判风险 | 住宅/家宽 IP 宽松；机房 IP 严（实测 #17 就是签名算对仍 403） |

对应的三条技术路线：

- **路线 A（推荐，本方案主线）**：自持一个专用账号的会话 → 走**移动端免签名接口**。签名门直接绕过（这个接口不需要 a_bogus），只需要身份门 + 过得去的 IP。实测 #10–#13 全通。
- **路线 B（补位）**：网页接口 + 自算 a_bogus → 实测只有 `comment/list` 通（#7），`detail` 不通（#6）。所以评论用 B，视频用 A。
- **路线 C（兜底 / 图文）**：第三方解析 API（douyin.wtf 官方服务带 API Key，或商用聚合 API）或自建 DTK 的 browser-rpc 模式。**"完全免账号"的唯一形态就是路线 C**：让服务商的常驻真浏览器去铸身份（它的 /parse 就是干这个的），你只需要一个 API Key，不用碰 cookie。今天它的公开 demo 挂了（#16），所以这条路只能靠「自建 + 住宅代理」自己跑，或者买商用 API。

## 3. 推荐架构

```
微信小程序
   │  用户贴链接（v.douyin.com/xxx 或 www.douyin.com/video/<id>）
   ▼
你们的后端 (api.yourdomain.cn)
   ├─ 1. 归一化：短链 302 解析 → 取 aweme_id / note_id
   ├─ 2. 查缓存：aweme_id → 已落地文件 + 元数据（Redis，命中直接返回）
   ├─ 3. 通道漏斗（任一成功即止，全部失败落 error）：
   │     ① 移动接口 detail（自持会话 cookie）          ← 视频/音频/封面/作者
   │     ② 网页 comment/list（a_bogus + 同 cookie）    ← 评论
   │     ③ 第三方解析 API（或自建 DTK）                ← 图文 / 视频兜底
   ├─ 4. 服务端代理下载（不要把抖音 CDN 直链给前端）+ 落 OSS/本地盘
   └─ 5. 前端只拿你们自己的域名 URL（等同现在的 B 站视频流程）
   ▲
   │  会话供给
会话管家（独立进程 / 定时任务）
   └─ 持久化 Chromium profile + 健康检查 + 保温 + 掉线告警 + 扫码重登
```

要点：
- **抖音直链带签名和过期时间**（`.../<token>/video/tos/...`，分钟~小时级）。**一定服务端落地再转发**，既避免直链过期，也避免前端跨域/微信域名白名单问题。
- 解析结果按 `aweme_id` 缓存，TTL 建议 24 h（元数据）/ 永久（已下载的文件）。重复请求不用再打抖音，这也是最重要的降风控手段。

## 4. 通道 A：移动端免签名接口（视频主力）

### 4.1 请求

```bash
curl -s "https://aweme.snssdk.com/aweme/v1/aweme/detail/?aweme_id=<aweme_id>&version_code=9.9.0&device_platform=iphone&aid=1128" \
  -H "User-Agent: Mozilla/5.0 (iPhone; CPU iPhone OS 17_0 like Mac OS X) AppleWebKit/605.1.15 (KHTML, like Gecko) Version/17.0 Mobile/15E148 Safari/604.1" \
  -H "Referer: https://www.douyin.com/" \
  -H "Cookie: sessionid=xxx; sid_tt=xxx; uid_tt=xxx; ..."
# → {"status_code":0,"aweme_detail":{...}}
```

- **不需要 a_bogus / x-bogus / msToken**，只要 `sessionid` 系登录态（实测 #10–#12）。
- 备选 host（同一接口，挂了就换）：`api.amemv.com`、`api3-normal-c-lf.amemv.com`。
- Android UA / `device_platform=android&version_code=30.0.0` 同样通，可做轮换降风控。

### 4.2 字段映射（直接对应你们的功能）

| 你们要的东西 | 字段 | 备注 |
|---|---|---|
| 标题/文案 | `aweme_detail.desc` | 话题标签也在里面 |
| 视频（无水印） | `aweme_detail.video.play_addr.url_list[]` | **3~4 个 CDN 地址，逐个试**；实测无 `playwm` = 无水印 |
| 高码率版本 | `video.bit_rate[].play_addr.url_list[]` | 取 `bit_rate` 最大者 |
| 带水印版（不要用） | `video.download_addr` | 有水印，只作参考 |
| 音频 / 原声 | `music.play_url.url_list[]` | 实测 `https://sf6-cdn-tos.douyinstatic.com/obj/ies-music/<id>.mp3`，可直接当音频下载 |
| 封面 | `video.cover` / `origin_cover` / `dynamic_cover` | `dynamic_cover` 是动图封面 |
| 时长 | `video.duration`（毫秒）、`music.duration` | |
| 作者昵称 | `author.nickname` | |
| **抖音号（给用户搜索）** | `author.unique_id` | ⚠️ 不是 `sec_uid`；`sec_uid` 粘到抖音搜索框搜不到人 |
| 作者主页 | `author.sec_uid` → `https://www.douyin.com/user/<sec_uid>` | |
| 点赞/评论/收藏/转发/播放 | `statistics.digg_count / comment_count / collect_count / share_count / play_count` | 评论总数就在这（实测 1997） |
| 作品类型 | `aweme_type`（0=视频，68=图文）、`media_type` | |
| 是否图文 | `aweme_detail.images[]` 非空 | 移动接口下图文会被 filter，见第 6 节 |

### 4.3 下载（实测可用）

```bash
curl -sL -o out.mp4 "<play_addr url>" \
  -H "User-Agent: Mozilla/5.0 (iPhone; CPU iPhone OS 17_0 like Mac OS X) AppleWebKit/605.1.15" \
  -H "Referer: https://www.douyin.com/"
file out.mp4   # 应为 ISO Media, MP4
```

坑：
- **UA 不对或没带 Referer → 403 或 0 字节**。必须 iPhone/Android UA + `Referer: https://www.douyin.com/`。
- 用 `url_list[0]` 慢了就换 `[1]`/`[2]`，别傻等；单条建议超时 20~30 s。
- 解析后**尽快下载**，直链会过期。

## 5. 通道 B：网页评论接口（评论主力，实测通）

```bash
# 需要在 URL 上带自算的 a_bogus（用开源实现，见下）
https://www.douyin.com/aweme/v1/web/comment/list/?device_platform=webapp&aid=6383&channel=channel_pc_web&aweme_id=<id>&cursor=0&count=20&...&a_bogus=<签名>
# 附带同一个登录 cookie
```

实测返回：`{"comments":[...18条], "status_code":0, "has_more":1, "min_cursor":..., "total":1997}`

- 分页：`cursor` 用上一次返回的 `min_cursor`，`has_more=0` 停止。
- 评论字段（常用）：`text`、`digg_count`、`reply_comment_total`（子评论数）、`user.nickname`、`user.unique_id`、`create_time`。
- 子评论：`aweme/v1/web/comment/list/reply/?item_id=<aweme_id>&comment_id=<cid>&cursor=0&count=10`（同签名机制）。
- **签名实现**：直接用开源仓库 `Evil0ctal/Douyin_TikTok_Download_API` 里的 `abogus.py`（`crawlers/douyin/web/`）。
  ⚠️ 实测同一个签名机制在 `comment/list` 上通、在 `aweme/detail` 上 403 —— 不要以为「detail 403 = 签名写错了」。
- **图文别走这条路**：`aweme/v1/web/aweme/detail/` 实测 403。

## 6. 图文（note / 图集）专项

实测：移动接口对图文一律 `filter_detail.filter_reason="images_base"`，换 4 组 `version_code/aid` 都一样（#14）；分享页 SSR 里也没有图片 URL（#15）。所以图文**只能**靠：

1. **第三方/自建解析服务**（推荐，成本最低）。以 douyin.wtf 的响应结构为例，图片在：
   - `data.media.images[i].url_list[]` —— ⚠️ 路径是 `media.images`，不是顶层 `images`；
   - **挑不带 `~tplv` 的那条 = 原图**（实测拿到 2160×2880）；带 `~tplv` 的是压缩预览图。
   - 动图（live photo）：`data.raw.images[i].video.play_addr.url_list[]` —— **普通解析里 `media.images[i].video` 恒为空**，那里 `live=no` 是假阴性，判定动图必须走 raw 接口。
2. **自建真浏览器**：注入 cookie 打开 `www.douyin.com/note/<id>`，让页面自己去调接口，抓页面自己的 200 响应（自己算签名/无 cookie 时实测是 200 空包）。
3. 图文页的音乐：`data.music.play_url` 可能是 `null`（PGC 版权曲）→ 需另取（raw 接口 / 页面播放流）。

产品建议：**第一版图文可以先不支持**，或只给「图文已识别，暂不支持下载」的提示，别为了图文拖慢视频主线的上线。

## 7. Cookie 自动供给了（回应用户诉求的核心）

目标：**用户永远不用手动给你 cookie**。做法 = 一次性登录 + 自动保温 + 自动告警 + 可快速重登。

### 7.1 账号准备

- 用一个**专用小号**（不要用私人号），1~3 个账号轮换更稳。
- 一次性人工操作：手机扫码登录。之后生命周期由服务维持。

### 7.2 会话寿命（实测）

`sid_guard=f0c713...%7C1789479874%7C5184000%7CSat, 14-Nov-2026 13:44:34 GMT`
→ 有效期 **5184000 秒 = 60 天**。活跃访问会续期（这是它比「每周找用户要 cookie」强的地方）。

> 注意：`sessionid` 会话与设备/IP 有一定绑定。**换了出口 IP 或换浏览器 profile 可能掉**，所以保温进程和业务进程尽量用同一个出口。

### 7.3 保温 + 自刷新（持久化 profile + 定时访问）

```python
# pip install playwright && playwright install chromium
from playwright.sync_api import sync_playwright

PROFILE = "/data/dy_profile"        # 持久目录，别放 /tmp
# 首次：headless=False 让人工扫码一次，之后 headless 常驻
with sync_playwright() as p:
    ctx = p.chromium.launch_persistent_context(
        PROFILE, headless=True,
        user_agent="Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36 "
                   "(KHTML, like Gecko) Chrome/126.0.0.0 Safari/537.36",
        viewport={"width": 1440, "height": 900}, locale="zh-CN",
        timezone_id="Asia/Shanghai",
    )
    page = ctx.new_page()
    page.goto("https://www.douyin.com/", wait_until="domcontentloaded")
    page.wait_for_timeout(6000)          # 让站点自己刷新 ttwid / msToken / UIFID
    cookies = ctx.cookies()              # 导出到 Redis/DB 给业务进程用
    ctx.close()
```

- **每 4~6 小时跑一次**（cron）：访问 `douyin.com` 首页 + 一次视频页，导出 cookie 覆盖到存储。
- 导出的是 `[{name,value,domain,...}]`，业务侧拼成 `name=value; ...` 的 Cookie 头即可。
- 用 **chromium 真浏览器**而不是纯 HTTP 请求：签名/风控指纹是页面自己算的，你白蹭。
- 别把 profile 放临时目录；容器里要挂持久卷。

### 7.4 健康检查 + 告警（必须有，否则掉线你都不知道）

```python
# 每 30 分钟一次
r = httpx.get("https://aweme.snssdk.com/aweme/v1/aweme/detail/",
              params={"aweme_id": "<一个固定不变的探针视频ID>",
                      "version_code": "9.9.0", "device_platform": "iphone", "aid": 1128},
              headers={"User-Agent": IPHONE_UA, "Referer": "https://www.douyin.com/",
                       "Cookie": cookie_from_store}, timeout=15)
ok = r.status_code == 200 and len(r.content) > 1000   # 空包 = 掉线，这是关键判据
```

- **判据是「响应体字节数」，不是 HTTP 状态码**：身份无效时抖音回的是 `200 + 0 字节`（实测 #8/#9）。只看状态码会漏判。
- 连续 3 次空包 → 触发告警（企业微信机器人/邮件）→ 人工扫码重登（把 7.3 的 `headless` 改 False，或用 `page.screenshot()` 把二维码发到群里扫）。

### 7.5 多账号轮换（可选，P1）

- 账号 A/B/C 各自独立 profile + 独立 UA，业务侧按请求数或错误率切换。
- 单账号请求也要控速：**解析类请求 1~2 QPS 上限**，别拿它当爬虫跑（这才是封号主因）。

## 8. 出口 IP：为什么建议挂家宽

- 实测：本机（香港家宽住宅 IP）+ 自算 a_bogus，`comment/list` 通；同一份代码在机房环境历史上多次被 403（含 `detail`）。Argus 是按出口 IP 打分的。
- 落地建议：
  1. 先在腾讯云机器上跑第 12 节探活，看**移动端 detail** 通不通（这条最可能通，因为它不吃签名）。
  2. 若通 → 先上线，别过度设计。
  3. 若不通/不稳 → 把「采集服务」放到家宽节点（例如你家 NAS / 树莓派 / 一台家里的小主机），腾讯云后端只做 API 网关和缓存，两者之间走内网穿透/隧道（frp、Tailscale 都行）。成本 ≈ 0，且 IP 是住宅 IP。**顺带还能让 cookie 和 IP 绑定稳定，会话更不容易掉**。

## 9. 你们自己的后端 API 设计建议

```
POST /api/douyin/parse
  { "url": "https://v.douyin.com/xxxx/" }         # 也接受 App 复制的整段分享文案
→ { "code": 0, "data": {
      "aweme_id": "...", "kind": "video|note",
      "title": "...", "author": {"nickname":"...","unique_id":"...","sec_uid":"...","url":"..."},
      "duration_ms": 27034, "cover": "https://cdn.you.com/covers/xxx.jpg",
      "video": {"url": "https://cdn.you.com/dy/xxx.mp4", "size": 4606368, "width":1080,"height":1920},
      "audio": {"url": "https://cdn.you.com/dy/xxx.mp3"},    # 原声/BGM
      "images": [],                                          # 图文才有
      "stats": {"digg": 0, "comment": 1997, "collect": 0, "share": 0}
  }}

GET  /api/douyin/comments?aweme_id=xxx&cursor=0
→ { "comments": [ {"text":"...","digg":..,"user":{"nickname":"..","unique_id":".."},"create_time":..} ],
    "next_cursor": 12, "has_more": 1, "total": 1997 }
```

工程要点：
- **输入归一化**：正则从分享文案里抠出 URL → 对 `v.douyin.com` 发请求拿 302 的 `Location` → 正则 `/(video|note|slides)/(\d+)` 取 ID。⚠️ 一定要包含 `slides`（图文短链会跳到 `/share/slides/<id>`）。
- **错误码分开**：`链接无效` / `作品已被删除或不可见`（抖音返回 404 或 filter 时）/ `解析服务繁忙`（第三方 5xx）/ `暂不支持图文`。前端文案才能说人话。
- **缓存**：`aweme_id` 维度缓存元数据 + 已落地文件；直链 TTL 短，别缓存直链。
- **存储**：视频落你们自己的 OSS/本地盘再给前端 URL（同现有 B 站方案）。这会显著增加带宽，建议评估：是否只缓存前 N 分钟 / 加个「转存」按钮触发。
- **限流**：小程序侧按用户 ID 限速；服务端对抖音侧 1~2 QPS。
- **弹幕**：抖音点播没有弹幕。别做假弹幕。

## 11. 探活清单（2 小时，全部可直接复制）

```bash
# 0) 换成一个真实的抖音视频 ID（自己 App 分享一条）
VID=7662997337493491129

# 1) 网络是否通（不是被墙）
curl -s -o /dev/null -w "%{http_code}\n" https://www.douyin.com/

# 2) 短链解析（拿 ID 的能力，不需要任何 cookie）
curl -sI "https://v.douyin.com/xxxxx/" | grep -i location

# 3) 移动接口：不带 cookie 应回 0 字节（这是基线，不是失败）
curl -s "https://aweme.snssdk.com/aweme/v1/aweme/detail/?aweme_id=$VID&version_code=9.9.0&device_platform=iphone&aid=1128" \
  -H "User-Agent: Mozilla/5.0 (iPhone; CPU iPhone OS 17_0 like Mac OS X) AppleWebKit/605.1.15" \
  -H "Referer: https://www.douyin.com/" -o /dev/null -w "%{http_code} %{size_download}\n"

# 4) 移动接口 + 你的登录 cookie（关键一试）
curl -s "https://aweme.snssdk.com/aweme/v1/aweme/detail/?aweme_id=$VID&version_code=9.9.0&device_platform=iphone&aid=1128" \
  -H "User-Agent: Mozilla/5.0 (iPhone; CPU iPhone OS 17_0 like Mac OS X) AppleWebKit/605.1.15" \
  -H "Referer: https://www.douyin.com/" -H "Cookie: $(cat dy_cookie.txt)" \
  -o /tmp/t.json -w "%{http_code} %{size_download}\n"
python3 -c "import json;d=json.load(open('/tmp/t.json'));print('status',d['status_code'],'| desc',d['aweme_detail']['desc'][:30])" 2>/dev/null \
  || echo "❌ 空包/非 JSON = 这台机器的出口 IP 或会话不被接受，走第 8 节家宽方案"

# 5) 直链下载（无水印验证）
#    从 /tmp/t.json 取 aweme_detail.video.play_addr.url_list[0] 后：
curl -sL -o /tmp/v.mp4 "<play_addr>" -H "User-Agent: Mozilla/5.0 (iPhone; CPU iPhone OS 17_0 like Mac OS X)" \
  -H "Referer: https://www.douyin.com/" && file /tmp/v.mp4
```

- 第 4 步拿到几十 KB 的 JSON → **腾讯云出口能用**，P0 直接开干。

## 12. 已知坑速查

1. **HTTP 200 + 空 body ≠ 成功**：身份/签名不过时抖音就是这么回的。判成功必须看响应体字节数（>1 KB）。
2. `author.unique_id` 才是「抖音号」，`sec_uid`（`MS4wLjABAAAA...`）在抖音里搜不到人。
3. `music` 在顶层（`aweme_detail.music`），不在 `video` 下。
4. 网页接口 `aweme/detail` + 自算 a_bogus 实测 403 —— 评论接口通不代表它通。
5. 图文接口一律 `filter_reason: images_base`；分享页 HTML 里没有图片 URL。
6. 抖音**点播视频没有弹幕**。
7. 短链跳转终点可能是 `/share/slides/<id>`（图文），正则必须带 `slides`。
8. 开视频 CDN 下载要 iPhone/Android UA + `Referer: https://www.douyin.com/`，否则 403/0 字节。
9. 别把抖音直链给前端：会过期、跨域、微信域名白名单都过不去 —— 服务端落地再转发。
10. 机房 IP 与住宅 IP 差别很大（本方案所有 ✅ 都是在住宅 IP 上测的）。
11. 第三方免费演示服务（如 douyin.wtf 的公开 demo）**会整站挂**（实测当天 `/parse` 502），只能当兜底，不能当唯一通道。
12. 一次请求别并发打抖音；1~2 QPS + 本地缓存是最重要的稳定性设计。
