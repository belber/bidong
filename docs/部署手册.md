# 部署手册

## 常用维护（日常用）

更新代码 / 配置并重启（**本地**执行）：

```bash
./deploy.sh --env --up   # 同步代码 + 上传 .env.prod + 远端重建启动（日常推荐）
./deploy.sh --up         # 只改代码、密钥没动时

本地启动：
cd /Users/belber/workspace/bidong/server
./dev.sh
```

看服务状态和日志（**服务器上**，进部署目录）：

```bash
cd /opt/bidong/server
APP_ENV_FILE=.env.prod docker compose ps                  # 各服务是否在跑
APP_ENV_FILE=.env.prod docker compose logs -f api --tail=200     # API 实时日志
APP_ENV_FILE=.env.prod docker compose logs -f worker --tail=200  # 机器人 worker
APP_ENV_FILE=.env.prod docker compose logs -f admin --tail=100   # 管理端
APP_ENV_FILE=.env.prod docker compose logs db --tail=100         # PostgreSQL
```

> 服务器上只有 `.env.prod`（`deploy.sh` 同步时会排除 `.env*`），而 compose 里的
> `env_file: ${APP_ENV_FILE:-.env}` 默认找 `.env`。所以**服务器上的每条 compose
> 命令都要带 `APP_ENV_FILE=.env.prod`**，否则会直接报找不到 env 文件。

**每次部署后确认迁移跑过**（改过模型/加过 alembic 版本时必查）：

```bash
APP_ENV_FILE=.env.prod docker compose logs migrate --tail=20
# 期望看到 "Running upgrade <旧> -> <新>, <说明>"，且最新一条是本次的版本号

APP_ENV_FILE=.env.prod docker compose run --rm migrate   # 没跑或失败时手动补跑
```

> 漏跑迁移的表现是"页面能开、但某些接口 500"，报错通常是
> `column ... does not exist`——代码已经带了新字段，库还停在旧结构。

日志文件（宿主机，按天轮转、保留 30 天）：

```bash
tail -f /opt/bidong/server/logs/api.log
tail -f /opt/bidong/server/logs/worker.log
tail -f /opt/bidong/server/logs/admin.log
```

管理端访问（8081 只绑本机，用 SSH 隧道，在你电脑上执行并保持运行）：

```bash
ssh -p <SSH端口> -N -L 8081:127.0.0.1:8081 <用户>@<服务器IP>
```

然后浏览器打开 `http://127.0.0.1:8081/admin/`，密码是 `server/.env.prod` 里的 `ADMIN_PASSWORD`。

数据库备份（**服务器上**）：

```bash
cd /opt/bidong/server && ./backup_db.sh   # 手动备份一次
```

每天 03:00 自动备份（首次配一次）：

```bash
crontab -e
# 文件末尾加一行：
# 0 3 * * * cd /opt/bidong/server && ./backup_db.sh >> /opt/bidong/backups/backup.log 2>&1
```

备份文件在 `/opt/bidong/backups/`，自动保留 14 天。

只改了配置（比如换 cookie / 密码）想让它生效，在服务器上：

```bash
cd /opt/bidong/server && APP_ENV_FILE=.env.prod docker compose up -d
```

常记：

- 机器人 cookie 失效 → 管理端「账号/Cookie」更新，不用改代码
- 数据库备份用上面的 `backup_db.sh`（数据在 `pgdata` 卷，删卷才会丢）
- HTTPS 证书由 certbot 自动续期，无需手动
- `.env.prod` 有改动时，部署记得带 `--env`

## 本地测试（自己电脑）

```bash
cd server
cp .env.example .env.local   # 首次，然后编辑
APP_ENV_FILE=.env.local docker compose up -d --build
```

## 首次部署（从零到上线，按顺序做一遍）

1. **前置**：

   - 域名 + ICP 备案 → A 记录指向服务器公网 IP
   - 服务器装 Docker：`curl -fsSL https://get.docker.com | sh`
   - 配 Docker 镜像源（腾讯云服务器直连 Docker Hub 很慢，必做）：

     ```bash
     sudo mkdir -p /etc/docker
     sudo tee /etc/docker/daemon.json > /dev/null <<'EOF'
     {
       "registry-mirrors": ["https://mirror.ccs.tencentyun.com"]
     }
     EOF
     sudo systemctl restart docker
     ```

   - 注册小程序拿到 AppID/Secret；建 COS 桶（公有读私有写）

2. **改变量**：

   - 本地 `deploy.env`（未跟踪，不进仓库）：`REMOTE_USER` / `REMOTE_HOST` / `REMOTE_PORT` / `REMOTE_DIR`，格式见 `deploy.sh` 顶部注释
   - `server/.env.prod`：所有 `CHANGE_ME_*`（数据库密码两处、`WECHAT_SECRET`、`COS_*`、`PUBLIC_BASE_URL=https://你的域名`）
   - `miniprogram/app.js`：`PROD_API_BASE` 换成 `https://你的域名`

3. **SSH 免密**（自己电脑，一次）：

   ```bash
   ssh-keygen -t ed25519            # 没有公钥才生成
   ssh-copy-id -p <SSH端口> <用户>@<服务器IP>
   ssh -p <SSH端口> <用户>@<服务器IP> "echo ok" # 能打印 ok 即配好
   ```

4. **同步代码**：`./deploy.sh`（若报 `Permission denied (13)`，先在服务器执行 `sudo chown -R 用户:用户 目标目录`）

5. **上传密钥文件**：`./deploy.sh --env --up` 会自动带 `.env.prod`（等价于手动 `scp server/.env.prod 用户@IP:目标目录/`）

6. **安装 logrotate**（服务器上，日志按天轮转）：

   ```bash
   sudo tee /etc/logrotate.d/bidong > /dev/null <<'EOF'
   /opt/bidong/server/logs/*.log {
       daily
       rotate 30
       compress
       missingok
       notifempty
       copytruncate
   }
   EOF
   sudo logrotate -d /etc/logrotate.d/bidong
   ```

   （目录按你的 `REMOTE_DIR/logs` 调整）

7. **HTTPS**（服务器上）：

   ```bash
   sudo apt install -y nginx certbot python3-certbot-nginx
   # 先建 80 反代配置（内容见下），再签证书
   sudo certbot --nginx -d 你的域名
   ```

   Nginx 配置 `/etc/nginx/conf.d/bidong.conf`（白名单版 + 限速）：

   ```nginx
   # 限速区必须写在 http 上下文；conf.d/*.conf 就是被 http 包含的，所以放这里合法
   limit_req_zone $binary_remote_addr zone=bidong_api:10m rate=20r/s;

   server {
       listen 80;
       server_name <你的API域名>;

       # certbot 续期依赖这条，必须保留，且要比 location / 更具体
       location ^~ /.well-known/acme-challenge/ {
           root /var/www/html;
       }

       # 只放行 API，其余一律断连
       location /api/ {
           limit_req zone=bidong_api burst=40 nodelay;
           limit_req_status 429;

           client_max_body_size 20m;

           proxy_pass http://127.0.0.1:8000;
           proxy_set_header Host $host;
           proxy_set_header X-Real-IP $remote_addr;
           proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
           proxy_set_header X-Forwarded-Proto $scheme;
           # 媒体中转下载要允许慢速长连接，避免 60s 默认超时把下载掐断
           proxy_buffering off;
           proxy_read_timeout 600s;
           proxy_send_timeout 600s;
       }

       location / { return 444; }
   }
   ```

   **为什么这么写**

   - 小程序的全部请求都在 `/api/` 下，封面走 COS，音频中转下载也是 `/api/cards/:id/download`，所以白名单不会误伤业务。
   - `return 444` 直接断连、不回任何内容，扫描器摸不到服务指纹，容器日志里也不会再刷 404。全网扫描打 PHP 路径的流量会在 Nginx 就被丢掉。
   - 顺带解决了 FastAPI 自带文档的暴露面：`/docs`、`/redoc`、`/openapi.json` 不在白名单内，会被 444 挡掉。如果你想调试时用，**不要**把它们加进白名单，改用 SSH 隧道：`ssh -L 8000:127.0.0.1:8000 -p <SSH端口> <用户>@<服务器IP>`，然后本地开 `http://127.0.0.1:8000/docs`。
   - `limit_req` 按客户端 IP 限速，`10m` 大约能存 16 万个 IP。20r/s 对一个小程序 API 足够宽松，`burst=40 nodelay` 允许页面首屏并发几个请求不被拦。真实瓶颈出现时再调 `rate` 和 `burst` 即可。
   - 管理端（8081）**不要**在这里加 location，保持只绑 `127.0.0.1:8081`，需要时用 SSH 隧道访问。

   **三个注意事项**

   1. `STORAGE_BACKEND` 是 `cos` 时封面走 COS，不需要放行 `/media/`。若哪天把它切回 `local`，封面会变成 `https://<你的API域名>/media/covers/...`，那时必须给 `/media/covers/` 补一条 location，否则小程序封面全部加载失败。
   2. 改完先跑 `sudo nginx -t && sudo systemctl reload nginx`，再验证，确认无误即可。

   3. `certbot --nginx` 会基于现有 server 块生成 443 配置，正常情况下会连 location 一起拷贝。签完证书后顺手 `cat` 一眼 443 那个 server 块，确认 `location /api/`、`location / { return 444; }` 和限速都还在——白名单只在 80 生效、443 全放行是这里最容易出现的事故。

   4. **云安全组必须放行 80 端口**。Let's Encrypt 的 HTTP-01 校验从 80 端口发起：只放行 443 的话证书能签发但**无法自动续期**，到期当天 HTTPS 直接失效、小程序所有请求失败。验证命令加 `--no-random-sleep-on-renew`，否则 certbot 会随机 sleep 最多 8 分钟才开工，看着像卡死：

      ```bash
      sudo certbot renew --dry-run --no-random-sleep-on-renew
      ```

      放行 80 后风险很低：白名单配置下它只返回 301 跳转和证书校验文件，其余一律 444。

8. **小程序侧**：
   - request 合法域名：`https://<你的API域名>`
   - downloadFile 合法域名：COS 封面域名 `https://<COS_BUCKET>.cos.<COS_REGION>.myqcloud.com`（保存封面到相册要用）
   - 提审前用管理端关掉敏感开关（@壁咚咚私藏 引导、分享等）

9. **验证**：

   ```bash
   curl -I https://你的域名
   curl https://你的域名/api/help/config   # 应返回 {"qq_group":""}
   ```

10. **日常回到文档顶部**：以后就用「常用维护」里的命令即可
