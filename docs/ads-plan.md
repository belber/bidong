# 广告接入方案（保守档）

> 状态：已选定 ｜ 日期：2026-10-07 ｜ 前提：已开通流量主，累计 500 用户

---

## 0. 选型结论

- ✅ 首页 Banner
- ✅ 收藏夹信息流（原生模板广告）
- ✅ 解析结果页 Banner
- ✅ 我的页 Banner（追加：底部空白大 + 绑定入口有访问量）
- ❌ 插屏广告（暂不接）
- ❌ 激励式视频广告（暂不接，待有增值功能再评估）

原则：**广告只出现在页面自然留白处，不挡任何核心操作路径**。上线后观察 1~2 周 eCPM / 填充率，再决定是否扩展到标准档。

## 1. 广告位明细

### 1.1 首页（pages/home）

| 项目 | 说明 |
|:--|:--|
| 组件 | `<ad unit-id="...">` 原生模板广告（横幅 20:7，优选模式） |
| 位置 | 输入框 + 解析按钮 + 引导卡片之后，页面底部 |
| 触发 | 页面加载即渲染，无交互 |
| 备注 | 全应用流量最大页面，主收入位之一；确保不挤压引导卡片滚动区域 |

### 1.2 收藏夹（pages/collect）

| 项目 | 说明 |
|:--|:--|
| 组件 | `<ad unit-id="...">` 原生模板广告（16:9 横版卡片，自定义模式） |
| 位置 | 收藏卡片列表中插入，每 5 张卡片插 1 条 |
| 触发 | 随列表滚动自然出现 |
| 备注 | 收益潜力最大的位置；样式需与卡片风格协调（封面图 + 标题布局） |

插入规则细节：

- 按收藏卡片的全局序号（跨月份分组累计）计算插入点，如第 5、10、15…条后插入。
- 不足 5 张时在列表末尾补 1 条；0 条记录时在空态引导下方展示 1 条。
- 「搜索 / 分区筛选」切换后重新计算（来源筛选已于 2026-10-14 去掉，收藏夹不再区分本机与 @壁咚咚）。
- **网格视图（2026-10-15 修订）**：**每个月份分组末尾固定一条整行横幅**，贴在分组网格的下方。
  - 不做「占一格」：横幅素材塞进网格就变成了卡片形态，与横幅本身的比例不匹配。
  - 也不做「网格内整行插入」：月份内卡片数是奇数时，整行会把最后一行顶出半格空洞；贴在分组边界上则天然整行、无空洞。
  - 网格视图不再按张数算间隔（每个分组一条），列表视图仍是「每 5 张一条 + 不足 5 张补末尾一条」；两者共用同一个 `unit-id`，只是容器与位置不同。
  - 广告加载失败只隐藏出错的那一条（`onAdError` 按 `slotKey` 定位：网格是 `feed-<月份>`，列表是 `feed-<序号>`）。

### 1.3 解析结果页（pages/result）

| 项目 | 说明 |
|:--|:--|
| 组件 | `<ad unit-id="...">` 原生模板广告（横幅 20:7，优选模式） |
| 位置 | 基本信息 / 出处等卡片内容之后，页面底部 |
| 触发 | 页面加载即渲染 |
| 备注 | 用户解析完会停留浏览，滚动到底部自然触达 |

### 1.4 我的页（pages/mine）

| 位置 | 组件 | 模板 | 说明 |
|:--|:--|:--|:--|
| 广告位 1（上） | `<ad unit-id="...">` | 横幅 20:7（优选模式） | 菜单卡片下方的留白区；沿用原「我的页底部」广告位 |
| 广告位 2（下） | `<ad unit-id="...">` | 横幅 20:7（优选模式） | 同上一块留白区；2026-10-15 新建的广告位 |

为什么放两条（2026-10-15 追加）：

- 该页没有列表内容：已绑定用户整页只剩「一张小卡片 + 三条菜单」，底部留白超过半屏，单条横幅填不满。
- 位置定稿（2026-10-15 当天下午调整）：两条都贴在菜单卡片下方的留白区，上下叠放，先旧位后新位；旧位沿用原广告位，历史数据不断档。
- 已知取舍：两条相邻，观感上接近广告墙。靠 32rpx 间距与同规格 20:7 横幅减轻；若这两条的填充率 / eCPM 明显低于其他页，先撤掉下面那条。
- 预期收益仍是最小的一档，以补曝光为主；数据若明显好于预期，再考虑其他页加位。

实现约定：

- 触发：页面加载即渲染，无交互。
- 兜底：两条各自记 `error`（`onAdError` 按 `slotKey` 定位：`mine-top` / `mine-bottom`），只隐藏出错的那一条，另一条照常展示。
- unit-id：两条各自独立的广告位（`MINE_BANNER_TOP` = 上条 = 原「我的页底部」位，`MINE_BANNER_BOTTOM` = 下条 = 新建位）。不共用一个 `unit-id` 有两个理由：一是流量主后台的曝光 / 点击 / eCPM 按广告位聚合，共用就分不清两条各自的表现；二是规避「同一 `unit-id` 在同一页面重复使用」的行为不确定性（官方文档未给出明确结论）。配置只用 `unit-id` 区分，页面代码两条完全一样。

## 2. 工程约定

### 2.1 广告位 ID 管理

- 所有 `unit-id` 收敛到前端常量文件 `miniprogram/config/ads.js`，按位置命名：
  - `HOME_BANNER` / `COLLECT_FEED` / `RESULT_BANNER`
  - `MINE_BANNER_TOP` / `MINE_BANNER_BOTTOM`（我的页两条，见 §1.4）
- 换位 / 下线只改一处。

### 2.2 信息流插入间隔

- 插入间隔固定为 5（`ADS.COLLECT_FEED_INTERVAL`），方便调优；不足 5 张时在列表末尾补 1 条，空态也展示 1 条。

### 2.3 加载失败兜底

- Banner / 原生模板都有 `error` 事件（`onError`）：
  - 广告拉取失败时**隐藏广告容器**（`wx:if` 控制），不留空白块、不产生页面抖动。
  - 同一页面有多个广告位时（我的页两条），按 `slotKey` 只隐藏出错的那一条。
  - 不做重试轮询，下次页面加载自然重试。

### 2.4 埋点（可选，低成本）

- 利用广告组件的 `onClose` / `onError` 事件 console 记录，便于排查填充问题；不做自定义上报，先看流量主后台数据。

## 3. 上线步骤

1. 微信公众平台 → 流量主 → 创建广告位：首页 Banner、收藏夹原生模板、结果页 Banner、我的页 Banner ×2（底部上下叠放，分开建，见 §1.4）。
2. 把 `unit-id` 填入 `config/ads.js`。
3. 前端接入（TDD：广告容器显隐逻辑可写单元测试；组件渲染本身依赖真机）。
4. 真机验证：
   - 广告正常展示时布局无抖动；
   - 断网 / 无填充时容器隐藏、无空白；
   - 收藏夹筛选、搜索、分组切换后广告插入点正确。
5. 提交审核 + 发布。
6. 上线后 1~2 周观察流量主后台：eCPM、填充率、曝光 / 点击。
7. 数据达标后，再评估升级标准档（首页 / 结果页加位 + 激励视频 + 收藏上限机制）；我的页两条若填充率太低，先撤掉上面那条。
