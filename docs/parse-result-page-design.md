# 解析结果页改版设计（字段化展示 + 媒体下载）

> 状态：待审阅 ｜ 日期：2026-09-01 ｜ 关联主文档：`docs/spec.md`

## 0. 背景与目标

现状：`miniprogram/pages/result` 形似 B 站播放页（封面置顶 + 「去查看」 + 复制信息），不符合「视频解析工具」的定位。

目标：把结果页改成「字段 + 内容」的解析产物清单，用户一眼看到解析出了什么；每个字段可单独复制/下载，顶部一键下载文本归档；新增三档媒体下载，并用后台开关控制。

## 1. 范围

本期做：

- 字段化结果页（13 个字段，见 §2）
- 三档媒体下载：有水印视频（含音频）、无水印视频（不含音频）、纯音频
- 弹幕读取与下载（文本 XML）
- 统计数：点赞 / 评论 / 收藏 / 投币
- 三个独立后台开关

本期不做（延后）：

- 音视频合流（无损封装，`ffmpeg -c copy`）
- 评论正文读取
- TV 端无水印片源（需 TV 登录 token）
- 管理后台 UI（开关用后端配置项实现）

## 2. 字段清单与交互

顶部只保留一个全局动作：

**「下载解析结果.txt」**：完整文本归档，包含元数据（标题 / UP主 / 发布时间 / 标签 / 简介 / 统计 / B站链接）+ 字幕全文 + 弹幕全文。

| # | 字段 | 内容与操作 | 空状态 / 开关 |
|:--|:--|:--|:--|
| 1 | 标题 | 复制 | 无标题 |
| 2 | up主 | 复制 | 未知 |
| 3 | 发布时间 | 复制 | 未知 |
| 4 | 标签 | 复制（`#标签` 格式） | 无标签 |
| 5 | 简介 | 复制（可展开） | 无简介 |
| 6 | 统计 | 点赞/评论/收藏/投币 四格并排，复制整行 | 显示 0 |
| 7 | 封面 | 预览 + 保存相册 | 无封面 |
| 8 | 有水印视频（含音频） | 选清晰度 + 下载到相册 | 开关关 → 整行隐藏 |
| 9 | 无水印视频（不含音频） | 选清晰度 + 下载到相册 | 开关关 → 整行隐藏 |
| 10 | 纯音频 | 下载（分享文件到聊天） | 开关关 → 整行隐藏 |
| 11 | 字幕 | 预览前若干条 + 复制全文 + 下载 `.srt` | **显示「无字幕」** |
| 12 | 弹幕 | 显示条数 + 复制 + 下载 `.xml` | **显示「无弹幕」** |
| 13 | 评论正文 | 暂不支持（本期不做） | — |

字段顺序已按「身份信息 → 统计 → 媒体资产 → 文本资产」组织。统计为 0 是内容而不是空，照常显示 0。

术语说明：本设计里「有水印视频」指 B站单文件流（`durl`，可能带官方台标水印）；「无水印视频」指 DASH 原始视频轨（不含音频），通常不带台标水印，但不保证去除 UP主自嵌水印；真正的 TV 端无水印片源不在本期范围。

## 3. 后端设计

### 3.1 后台开关（三个独立配置项）

| 配置项 | 默认值 | 控制 |
|:--|:--|:--|
| `ENABLE_WATERMARKED_VIDEO` | `false` | 有水印视频（含音频） |
| `ENABLE_CLEAN_VIDEO` | `false` | 无水印视频（不含音频） |
| `ENABLE_AUDIO` | `false` | 纯音频 |

解析返回与下载接口都读这三个开关：前端据此隐藏对应行，后端在下载接口再校验一次，双保险。

### 3.2 解析返回新增字段

`POST /api/parse` 的 `ParseResult` 在现有 `CardOut + subtitles` 基础上增加：

- `stats`：`{ like, reply, favorite, coin }`，对应点赞 / 评论数 / 收藏 / 投币
- `danmaku_count`：弹幕条数
- `media`：`{ watermarked, clean, audio }`，三个布尔值来自 §3.1 开关

统计数与弹幕条数来自 `view` 接口的 `stat` 字段，**不落库**，解析时现取；已存在卡片重新解析时也刷新这两个瞬时值。

### 3.3 新增接口

沿用现有 `/api/cards/{card_id}` 的鉴权与错误处理方式：

| 方法 | 路径 | 说明 |
|:--|:--|:--|
| GET | `/api/cards/{card_id}/media-options?type=watermarked\|clean\|audio` | 返回可选清晰度列表（`qn + label`），不返回 B站原始 URL |
| GET | `/api/cards/{card_id}/download?type=...&qn=...` | 中转流式下载，返回文件流 |
| GET | `/api/cards/{card_id}/danmaku` | 现取并转发弹幕 XML |
| GET | `/api/cards/{card_id}/export?kind=txt\|srt` | 导出文本文件（txt 全量归档 / srt 字幕） |

`type` 与三档的对应：

- `watermarked` → B站单文件流（`durl`，音视频已合并）
- `clean` → DASH 视频轨（不含音频）
- `audio` → DASH 音频轨

### 3.4 `BiliClient` 新增能力

- `get_video` 补充返回 `stat`（点赞/评论/收藏/投币/弹幕条数）
- `get_playurl(bvid, cid, fnval)`：`fnval=1` 取 `durl`，`fnval=16` 取 DASH 音视频轨，解析出各清晰度
- `get_danmaku(cid)`：取 `comment.bilibili.com/{cid}.xml` 返回文本

仓库已有 `WbiSigner`（`server/app/services/wbi.py`），字幕接口已在使用，播放地址签名可复用。

### 3.5 下载数据流（中转流式 + 按需取链）

媒体下载不落盘到我们服务器，每次用户点击下载时现取一份新的 B站签名流：

1. 前端调用 `media-options` 拿到可选清晰度
2. 用户选定清晰度后，前端 `wx.downloadFile` 请求 `download` 接口（带鉴权头）
3. 后端校验开关 → 现调 `playurl` 取新流 → 用 `httpx.stream` 逐块转发给小程序，带 `Referer` / `UA`，支持 `Range` 续传
4. 前端按字段落盘：视频 → `wx.saveVideoToPhotosAlbum`，封面 → `wx.saveImageToPhotosAlbum`，音频 → `wx.shareFileMessage` 分享文件到聊天

封面不走 B站中转：封面已转存在自己域名（`cover_url`），前端直接下载到相册。

## 4. 前端设计

`miniprogram/pages/result` 从「视频页样式」改为「字段列表」：

- 每行：左侧字段名，右侧内容 + 操作按钮
- 三档媒体行受 `media` 开关控制，关闭则整行隐藏
- 字幕默认只显示前几条，展开后「复制全文 / 下载 .srt」
- 弹幕显示条数，下载 `.xml` / 复制
- 顶部单个按钮「下载解析结果.txt」

文本导出（`.txt` / `.srt`）走 `export` 接口，由后端组装并返回 `Content-Disposition` 附件，避免前端生成临时文件。

## 5. 空状态与错误处理

- 字幕 / 弹幕 / 标签 / 简介为空时显示「无字幕 / 无弹幕 / 无标签 / 无简介」，不隐藏字段
- 统计为 0 显示 0
- 开关关闭：前端整行隐藏，后端返回 403 兜底
- B站 `playurl` 失败或 412 风控：返回友好错误，前端提示重试，并保留「去 B站查看」兜底
- 无水印视频高清档需要登录态时，`media-options` 只返回匿名可得的清晰度

## 6. 测试计划（TDD）

后端（pytest + respx，沿用 `tests/test_bilibili.py` 的 mock 风格）：

- `get_video` 能解析 `stat` 各字段
- `get_playurl` 能区分 `durl` 与 DASH，正确列出清晰度
- `get_danmaku` 成功与失败（空/异常）两种情况
- `media-options` 在开关开/关时的行为
- `download` 在开关关闭时返回 403，开启时转发字节流
- `export` 的 txt 包含元数据 + 字幕 + 弹幕，srt 只含字幕
- 解析返回新增字段的序列化

前端：`result` 页字段渲染与空态；SRT/汇总文本生成、清晰度列表映射等纯函数。

## 7. 风险与边界

- 视频/音频下载踩 B站用户协议与版权线：仅定位个人自用工具，三档默认关闭，审核期间关闭
- 中转流式让服务器 IP 直面 B站 CDN，存在 412 风控风险：低频、按需取链、可降级「去 B站查看」
- 音频无法存进相册：采用「分享文件到聊天」交付
